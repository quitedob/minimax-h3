# /video 手机体验修复（2026-09-11）

## 范围与约束

- 按用户指定的 frontenddebugger 工作流：文档独立扫描 → 前端/后端契约独立扫描 → 主协调者核实 → 浏览器/截图 → 修复与回归。单页聚焦审计，不扩展为模型工程全库扫描。
- 目标：手机优先、适合非技术使用者；每条视频有提示词、视频时长、生成用时；AI 必须收到所选秒数。
- 原生 HTML/CSS/JS，Python aiohttp 提供页面与接口，没有前端构建依赖。
- 保持 Turbo 8 步（4–8 可选）、现有分辨率与帧数网格、LoRA/SolAttn/EasyCache/SDPA、模型文件、SSH 与云端路由不变。无 GPU 生成验收。
- `/video` 每次 GET 读取运行目录 HTML，允许仅更新页面而不重启模型服务。

## 文档核对

`docs/devlog.md` §17–19 是当前依据。§17 的默认20步/至少10步已被 §18 的默认8步、4–8范围覆盖；旧云端8188说明已被18188反向隧道覆盖。既有磁盘列表、预览 `/view`、下载 `/h3/download` 和公开共享队列语义保持。

§17 仅声称响应式 CSS/HTTP 可用，并没有手机视觉或交互验收，不能当作完整 UX 合格证据。旧视频未记录的生成耗时无法通过创建日期或视频时长推算。

## 已修复

| 优先级 | 原问题与根因 | 修复 |
|---|---|---|
| P1 | `pollTimer` 在提交函数内声明，完成处理访问不到，异常又被空 catch 吞掉 | 统一轮询生命周期，成功/失败解锁，刷新恢复当前任务；丢失历史时检查队列并提示查作品 |
| P1 | AI 预览请求和图内 AI 直出均没有时长；确认时重新读取设置导致时长错配 | 所有网页 AI 路径统一 `/h3/prompt`，在 API 专用 user_text 副本加入“这是一个 N 秒的视频”；请求及确认阶段锁定参数快照 |
| P1 | 提示词和视觉描述拼入 innerHTML，`<d>` 等被解析且可能注入元素 | 用户/AI/文件数据使用 textContent 或完整转义；标签按原文显示 |
| P1 | 可重复确认；空提示词可提交 | 原子领取待确认数据、空值校验；快速完成后的第二次点击有700ms去抖 |
| P1 | 制作耗时可能把排队算进去、提前写入，失败立即丢待写记录 | 仅根据成功历史的执行起止时间与真实输出文件名写入，保存成功才清理，失败重试；未知显示“未记录” |
| P2 | 手机把输入缩到14px、信息缩到10px，按钮与媒体操作难找 | 输入16px，主要控件44–48px；常用时长/清晰度外置，手机底部单一主操作；顶部直达视频列表 |
| P2 | 视频标题只留五字，三个关键信息藏在折叠项内 | 常显提示词摘要、视频时长、生成用时；长提示词可展开全文；独立播放与下载按钮 |
| P2 | 定时整块重建列表导致焦点、展开状态或播放被打断 | 文件/任务按键复用 DOM；新增作品不会把当前第6条播放器挤出展示范围 |
| P2 | 缺少断连/错误/空状态、草稿恢复及键盘操作 | 独立请求降级与刷新、草稿/待确认恢复、语义化 tab/details/button、焦点样式、live region、减少动态效果 |

生成进度不再把采样步数当成整条任务完成百分比，也不根据排队时间推算精确剩余秒数。视频默认不预加载，用户点击后页内播放；媒体元数据加载后显示实际播放秒数。
